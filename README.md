# 投资命题多证据验证器

把一句主观投资命题拆成若干条**能被数据证伪**的子问题，逐条调用真实数据取证，
为每条证据标注**支持 / 反对 / 无法验证**，处理证据冲突，并产出一张
「什么信息变了，结论就得改」的反转条件表。

它不判断这只股票会不会涨。它只回答一件事：**这句话，现有证据支持到什么程度。**

## 二、用户

**主要用户：需要为自己的一条判断找证据、并且要对结论负责的人。**

- 自己写投资笔记、需要在动手前把逻辑过一遍的**个人投资者**；
- 要审阅他人观点、需要快速定位「这句话哪里没证据」的**研究员 / 分析师**；
- 正在学习「怎么把一句直觉变成可检验命题」的**学生与新入行者**。

**他们的处境**：手上有一句听来的、或是自己想的判断（「估值跌了但公司没变差」
「利润涨了，肯定是主业变好了」），想认真验证一遍，但
① 不知道这句话到底该拆成哪几个问题；
② 不知道每个问题该看什么指标、多少算过关；
③ 取到的数据对不上口径；
④ 最要命的是——**无法验证的部分会被悄悄跳过，最后得到一个看起来很完整的结论。**

**本产品存在的理由就是第 ④ 条。** 它把「查不到」当作一等公民：
每个子问题要么给出三态之一，要么给出「为什么查不到、需要什么、去哪拿」。

**明确的非用户**：想要买卖信号、想要目标价、想要标的质量排名的使用者。
本产品**结构性地**不提供这些——不是没做，是不做。理由见「六、边界」。

## 三、设计

### 3.1 主链路

```text
命题解析 → 拆解与澄清 → 取数 → 逐条取证与判定 → 冲突检测 → 结论聚合 → 反转条件表
                                                                    ↘ 比较 / 追问 / 存为研究任务
```

对应题目要求的九个环节，落点在下面这张表里：

| 环节 | 落在哪 | 关键设计 |
| --- | --- | --- |
| M1 命题解析 | `engine/parse.py` | 三类命题（背离 / 归因 / 传导）各有不同判据，先分类再拆解 |
| M2 澄清与修订 | `parse.py` → `ParsedThesis.v1/v2` | 澄清问题**可回答**；输出 v1→v2 的**逐字段 diff**，改了什么、为什么改，全部可见 |
| M3 子问题拆解 | `templates/gold.py` + `engine/run.py` | 模板手工精写，LLM 只做实例化；五字段缺一不可 |
| M4 取证 | `engine/executors.py` | 18 个执行器，每条都要给出判定规则与阈值 |
| M5 判定 | `schemas.py` 的类型约束 | 三态；判为「无法验证」必须附三问详情 |
| M6 冲突处理 | `engine/pipeline.py::detect_conflicts` | 五类冲突，按固定优先级裁决，强制留下残余不确定性 |
| M7 结论聚合 | `pipeline.py::aggregate` | 合取式判定；措辞受限；覆盖度自评 |
| M8 反转条件表 | `pipeline.py::falsification_conditions` | 八列，含**阈值依据** |
| M9 继续用 | `main.py` + `ResearchPanel.jsx` | 横向比较 / 追问 / 保存为研究任务 |

### 3.2 三个决定了这个产品长什么样的判断

**判断一：把约束写进类型系统，而不是写进 README 靠自觉。**

`schemas.py` 里，一条证据缺任何一个字段就**构造不出来**：

- `Provenance` 的来源 / 报告期 / 口径 / 单位都做了非空校验；
- `Evidence` 判为「无法验证」但没带三问详情（原因分类 / 需要什么 / 何时何地可得）→ 直接抛错；
  **反过来，非「无法验证」的证据带了这份详情，也抛错**——两个方向都堵死；
- `SubQuestion` 的五个必填字段不接受 `-` / `N/A` / `待定` / `无` 这类占位符；
- `UnverifiableDetail` 的三问同样拒绝空串和占位符。

这条约束在开发期抓到了三次我自己的 bug——执行器漏传详情，页面会直接崩，
而不是安静地渲染出一张没有失败原因的卡片。

**判断二：证据冲突不做和稀泥。**

同一个页面上出现方向相反的两条证据时，写「综合来看影响中性」是最省事也最没用的做法。
本产品要求每条冲突必须给出**性质 / 裁决依据 / 裁决过程 / 残余不确定性**四段，
且裁决必须援引一套事先定好的优先级（口径一致性 → 数据新鲜度 → 来源权威性 → 样本量），
不允许临场拍脑袋。

具象的例子：贵州茅台「估值回落但基本面未恶化」这条命题，
收入端同比 +1.47%（未恶化）与归母净利润同比 −1.95%（已恶化）同时成立。
这不是数据打架，是**两条真实且同口径的数据对同一个问题给出了相反回答**。
产品给出的裁决是：以归母净利润为判定主证据——因为「基本面」在投资语境下
最终指向股东的获利能力，而非经营规模；同时把收入端证据并列保留，不折叠成单一数字。
残余不确定性也照实写下：利润下滑是一次性的还是结构性的，扶摇的利润表接口不含
营业外支出明细，本产品**无法区分**。

**判断三：反转条件表的「阈值依据」一栏不许空着。**

「若基本面变化需重新评估」这种话谁都会写。本产品要求每一行回答八个问题，
其中最后一栏必须说清**为什么是这个数**——来自会计分界（收入同比 0%）、
来自本产品判据的区间边界（现金含量 0.8 倍）、还是来自模板预设（周期性 5pp 标准差）。
测试里有一条断言专门守着这一栏，并检查它的措辞里必须出现可辨识的出处标记。

### 3.3 界面上的两条自我约束

- **三态语义色贯穿全站**，且颜色只用来表达「证据指向哪一边」，不用来表达涨跌。
- **图表全部手写 SVG，且纵轴不截断、不做对数变换、不用双轴。**
  截断纵轴能把 3% 的波动画成悬崖，双轴能让两条无关的曲线看起来严丝合缝——
  这两种手法在本产品里被明确禁止，代码注释里写明了原因。
  估值分位图同时画出「本产品重建值」与「官方 pe_ttm」，并把两者的相对偏差标在图上。

### 3.4 澄清环节是可以回答的，而且回答必须改变下游

题目要求的主链路里有一句「澄清并**修订**投资命题」。只把澄清问题列出来、
再附一段默认假设，是把「澄清」做成了表单；真正的修订得让用户说得上话。

所以「命题修订」区块里的每个选项都能点。点完按「按我的回答重跑」，
整条链路带着用户的回答重算一遍。三件事是硬约束：

1. **回答的原话进 v2 的前提**，不被默认假设顶掉；v2 的说明也会注明
   「其中 N 条前提由用户指定」，是谁给的前提写在明面上。
2. **回答必须落到子问题上**，否则就是装饰。落地动作只有四种，全部登记在
   `parse.py` 的 `ANSWER_EFFECTS` 一张表里，说明文字与实际行为同源：

   | 动作 | 含义 | 例子 |
   | --- | --- | --- |
   | `unverifiable` | 该子问题在本数据源下无法按用户指定的口径重算，改判为无法验证 | 参照系选「与同业比」→ SQ-01 改判（本产品只对用户指定的那一只标的取数） |
   | `drop` | 该子问题移出本轮范围，并在「未覆盖的分解层」中显式声明 | 口径收窄为「仅收入与利润」→ 现金含量那条移出并声明 |
   | `limitation` | 不改判定，给结论追加一条适用边界 | 「不确定是否发生过重组」→ 边界里写明该假设未经核实 |
   | `none` | 该选项与产品默认一致，下游不变——**如实说明它什么都没改** | 「与自身历史比」 |

3. **未回答时的行为逐字不变。** 四条例题的结论写进了测试、README 和演示视频，
   一个新功能顺手改掉默认假设，等于把例题的结论换掉。这条由
   `test_no_answers_is_byte_identical_to_before` 守着：不传 `answers` 与传空字典，
   `model_dump` 除 `run_id` / `created_at` 外必须完全相同。

**自定义回答（不在选项内的）会被如实标记为「不改变下游」**，而不是硬套到最接近的预设口径上。
用户写「与同业比：沪深300 成分股」这种带冒号的长回答也不会被截断——
早先的前提是从一段文案里 `split("：")` 截出来的，回答里只要有一个冒号就会静默丢掉前半句。

浏览器里的验收是 `npm run ui:clarify`：真实点击选项 → 重跑 → 断言结论随之改变、
v2 引用了原话、且全程零控制台错误、无 `**` 泄漏。

## 四、AI 在产品里的角色

**AI 是产品的一个部件，不是产品的替身。** 具体分工：

| 环节 | 谁做 | 为什么 |
| --- | --- | --- |
| 命题分类 / 澄清问题生成 | **LLM 优先**（配了 `ANTHROPIC_API_KEY` 时） | 自然语言的分类与提问是 LLM 的强项 |
| 命题分类（兜底） | 规则引擎 | 无凭据 / LLM 超时 → 关键词与句式规则接管 |
| 子问题拆解 | **手工模板，LLM 不参与** | 见下 |
| 取数与判定 | **纯代码，LLM 不参与** | 见下 |
| 结论措辞 | **纯代码拼装** | 见下 |

三条 LLM 不参与的边界，理由各不相同：

1. **拆解不交给 LLM。** 子问题必须满足五字段（指标 / 数据源 / 时间窗 / 判定规则 / 阈值），
   而这五字段的可信度取决于「数据源是否真的能被调用、阈值是否有依据」。
   LLM 生成的子问题看起来总是很合理，但它会写出「参考行业景气度数据」这种
   本产品根本取不到的来源。模板是手工精写的，LLM 只做实例化。
   `templates/gold.py` 里三类命题共 18 条子问题，每条都写明了它为什么能验证命题。

2. **判定不交给 LLM。** 每条证据的三态由数值和事先写定的判定规则比较得出，
   代码可读、可测、可复现。让 LLM 看着数字说「我觉得这算支持」，
   等于把整个产品最需要一致性的部分交给了概率。

3. **结论措辞不交给 LLM。** 结论的每一句话都由实际的三态组合拼装而成。
   这条规则是被一次真实 bug 逼出来的：早先结论里写死了「收入端与毛利率端未能提供支持」，
   而宁德时代归因型的收入端其实是支持态——页面上的结论和证据卡自相矛盾。
   现在措辞从真实三态生成，写死的话术在代码里不存在。

**LLM 也参与了开发过程本身**（写测试、查缺陷、写文档），
这部分记录在 [`docs/AI使用与验证记录.md`](docs/AI使用与验证记录.md)，
包含 AI 出过的错、怎么发现的、以及哪些判断不能交给 AI。

### 5.1 一个必须说明的重建：历史估值分位

扶摇**不提供历史估值序列**，只提供最新估值快照。但「估值是否回落」这条命题
必须有历史分位才能回答。本产品的做法是重建：

```text
PE(t) = 前复权收盘价(t) ÷ EPS_TTM(t)
```

`EPS_TTM(t)` 用披露日阶梯函数——某期财报在它的披露日之后才生效，
避免用到当时市场上还不存在的数字。重建序列**自带三重自校准**：

1. 口径推断（比较累计口径与单季口径，确认该标的的季报是哪一种）；
2. 与官方 `pe_ttm` 快照对表，算出相对偏差；
3. 前复权与不复权两条序列交叉验证，分位相差超过 25 个百分点时触发冲突裁决。

实测偏差：中国平安 28.04%、贵州茅台 9.35%、比亚迪 30.04% —— 均在 35% 容差内；
**宁德时代 43.25%，超容差**，此时该条证据自动降为中等置信度，
并在界面上以冲突卡片的形式说明「重建值的绝对水平不可作为精确依据，只能读趋势」。

**所有重建值在界面上都与官方值并列展示，不做合并、不做平均。**
读者永远知道哪个数字是官方的、哪个是本产品算的。

## 六、边界

### 6.1 做不到，且写进产品里的

| 做不到的事 | 原因 | 产品怎么处理 |
| --- | --- | --- |
| 量价拆分（volume / rate） | 扶摇不提供产销量与分产品单价 | 在拆解结果中**显式列为跳过层**并给出原因，不默认跳过 |
| 业务结构拆解（mix） | 不提供分部收入 | 同上；传导型命题的核心前提因此不可验证 |
| 汇率影响（fx） | 不提供外币敞口 | 同上 |
| 行业景气度与周期位置 | 不提供行业数据 | PE 分位**不解读为「低估」**，只陈述「处于自身历史 N 分位」 |
| 非经常性损益明细 | 不提供营业外支出科目 | 用「加权 ROE − 扣非加权 ROE」做代理，并声明这是代理口径 |
| 定时监控与推送 | 未做 | 反转条件表保存为研究任务，到点人工复核 |

### 6.2 不做，且是刻意不做的

- **不给出买入 / 卖出 / 持有建议，不给目标价，不预测涨跌幅。** 测试里有一条断言
  会扫描所有结论文本，出现这类措辞直接失败。
- **不做标的评分与排名。** 横向比较多标的时只并列展示证据构成，
  接口返回的 `note` 里写明了理由：排序会把研究工具变成荐股工具。
- **不用模拟数据顶替真实数据。** 无凭据时降级到真实快照并在界面明示；
  快照也没有时，所有子问题返回「无法验证」并附带补齐路径——
  而不是编一组看起来合理的数字。

### 6.3 这个产品会出错的地方

- 重建 PE 的绝对水平在除权除息密集的年份附近可能偏移（趋势方向对口径不敏感，仍可用）；
- 关键词分类在句式复杂时会误判命题类型（如把传导型读成归因型），
  最终版扩充了关键词表，但这不是一个收敛的解法；
- 标的消歧依赖检索接口，命题里若是简称或别称，可能匹配到错误标的。
  产品会把**逐个尝试的候选名与最终命中的标的**写进运行日志并展示，便于人工核对。

## 七、未做事项

按「如果再多一天会做什么」排序：

1. **接入 iFinD MCP**，补上公告与研报，让分部收入与非经常性损益明细不再依赖代理口径。
   这是当前最大的能力缺口——传导型命题现在完全卡在「不知道公司靠什么赚钱」。
2. **持久化。** 目前运行记录与已保存任务都在内存里，进程重启即丢失。
   交付场景下够用，但不是产品该有的样子。
3. **定时监控。** 反转条件表已经给出了下次披露时点，但没有任何东西会在那天提醒用户。
4. **澄清回答只覆盖三类命题的 24 个预设选项。** 用户可以选，也可以自己写一句，
   但自定义回答只会进 v2 的前提，不改动任何子问题——没有对应的数据与判据可以套。
   要支持自由口径，得先有能按任意口径重算的取数层。
5. **子问题拆解的 LLM 实例化。** 模板目前是三类命题各一套，无法适配更细分的命题句式。
6. **多轮追问。** 追问目前是「展开已有证据」，不能就追问的答案继续追问。

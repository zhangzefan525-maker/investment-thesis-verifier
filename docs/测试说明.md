# 测试说明

本产品的核心主张是「**把约束写进代码，而不是写在文档里靠自觉**」。
测试就是这句话的兑现方式：文档里承诺的每一条产品约束，
都对应一条会失败的断言。约束失效时测试变红，而不是等读者发现。

---

## 一、怎么跑

```bash
# 后端：全部测试，完全离线，不需要凭据、不发起任何网络请求
cd backend && python -m pytest tests -q
# → 216 passed in ~2s

# 前端：先构建，再跑真实浏览器冒烟检查（需后端已在 8000 端口运行）
cd frontend && npm run build
cd backend && uvicorn app.main:app --port 8000 &     # 另一个终端
cd frontend && npm run ui:smoke
# → UI 冒烟：全部通过（退出码 0）
cd frontend && npm run ui:clarify
# → 澄清环节验收：全部通过（退出码 0）
```

`ui:smoke` 需要 `playwright`（已列入 `devDependencies`）。
首次使用需 `npx playwright install chromium`。

---

## 二、为什么后端测试敢说「完全离线」

`tests/conftest.py` 里有两条**硬规则**，都由代码保证，不靠自觉：

1. **`no_network`（autouse）** 把 `socket.socket.connect` 与 `connect_ex` 换成直接抛异常的桩。
   任何人若把 provider 换成真实客户端，测试会当场变红，而不是悄悄发出一次真实请求。
2. **`offline_env`** 主动清掉进程里可能存在的 `ANTHROPIC_API_KEY` /
   `HITHINK_FINANCE_API_KEY`。不清理的话，解析层会被 LLM 分支接管、取数层会被真实接口接管，
   「离线」就只是口头承诺。

第三条是纪律而非机制：**断言里出现的每个数值都来自实跑结果，不是照抄产品文档。**
文档会过期，实跑不会。

## 四、主链路覆盖

四个案例覆盖三类命题、三种结论，**每一例都是实跑确认过的期望值**
（写在 `conftest.py` 的 `EXPECTED` 里，不是从文档抄的）：

| 案例 | 命题 | 类型 | 期望结论 | 关键断言 |
| --- | --- | --- | --- | --- |
| 贵州茅台 | 估值已回落但基本面并未恶化 | 背离型 | **不支持** | 收入 +1.47% 与归母净利 −1.95% 相向，冲突被检出且裁决引用了优先级 |
| 中国平安 | 估值已回落但基本面并未恶化 | 背离型 | **支持** | 三态均为支持，PE 处于自身历史低分位 |
| 宁德时代 | 盈利改善来自主营业务 | 归因型 | **不支持** | 毛利率 −1.09pp，主判据（非经常性损益代理）未通过 |
| 宁德时代 | 碳酸锂涨价挤压利润空间 | 传导型 | **证据不足** | 3 条子问题因数据源结构性缺失判为无法验证 |

除结论外，每例都跑一遍**全链路不变量**：

- `test_run_completes_without_errors` —— 失败清单为空
- `test_resolved_target_matches_expected` —— 标的消歧命中预期
- `test_every_evidence_obeys_unverifiable_contract` —— 三态与三问详情的双向约束成立
- `test_every_evidence_is_traceable` —— 每条证据都能追到来源、报告期、口径
- `test_counts_add_up` —— 三态计数与证据条数自洽
- `test_fixture_mode_is_declared` / `test_evidence_snapshots_are_marked_as_frozen`
  —— 非实时数据必须在界面上被声明为非实时
- `test_every_sub_question_has_an_executor` —— 模板里没有「拆得出但取不到」的子问题
- `test_confidence_is_declared_on_every_evidence` —— 置信度逐条声明

## 五、接口异常覆盖

扶摇的返回**恒为 HTTP 200**，业务状态藏在响应体的 `code` 里。
「只看 HTTP 状态码」是这类接口最典型的错，因此失败路径被单独测了一层。
`FixtureProvider` 在这里反向使用：**故意让它取不到数据**，看产品会不会编一个出来。

| 测试 | 构造的异常 | 断言 |
| --- | --- | --- |
| `test_unknown_ticker_search_returns_err` | 检索一个不存在的标的 | 返回 `Err`，不是空列表 |
| `test_missing_fixture_route_returns_err_not_empty_list` | 快照目录里没有这条路由 | `Err`；**空列表是被明确禁止的返回值** |
| `test_unknown_target_chain_reports_failure_without_fabricating` | 整条链路无数据 | 报失败，且不产生任何编造数字 |
| `test_provider_without_any_fixture_returns_err` | 全新的空快照目录 | `Err`，不崩、不静默 |

这些 `Err` 在 UI 上不会消失：上游统一汇入**失败透明清单**，
没有失败时也会显示「本次失败清单为空」——沉默会被误读成藏起来了。

**未覆盖**：真实网络层的超时、限流（`4001`）、鉴权失效（`2003`）等状态码分支
只做了单元级判断，没有对着真实接口跑过故障注入。

## 六、合规边界覆盖

| 测试 | 断言 |
| --- | --- |
| `test_no_stock_recommendation_wording` | 结论陈述、每条证据的推理链与命题、覆盖度说明中，不得出现 `买入 / 卖出 / 建议持股 / 目标价 / 预计涨跌幅 / 推荐` |
| `test_disclaimer_is_present_and_scoped` | 免责声明存在且写明「不构成任何投资建议」 |
| `test_limitations_disclose_the_rebuilt_caliber` | 重建口径与数据源能力边界写进结论的适用边界，不能只藏在代码注释里 |
| `test_decomposition_declares_skipped_layers` | volume / rate / mix / fx 四层做不到的，必须显式列为跳过层并给出原因 |

「不做标的评分与排名」的边界由接口设计守：`/api/compare` 只并列返回证据构成，
不做排序，`note` 字段里写明理由。

## 七、渲染契约覆盖（第 6 层）

这一层是一次真实泄漏逼出来的。传导型命题的判定规则里写着
「成本率必须\*\*上升\*\*且毛利率下降 >1pp」，而拆解面板当时是裸渲染，
于是屏幕上原样出现了两个星号。这种错**不报异常、不崩页面**，
只是静静地让读者看到一串符号——最难靠人工发现的那一类。

`test_markdown_emphasis_stays_inside_rendered_fields` 递归遍历整份运行结果，
收集所有含 `**` 的字符串，断言它所在的字段在 `MARKDOWN_FIELDS` 清单内。
清单之外的任何位置带 `**` 都是 bug：要么去掉星号，要么把那个槽位接上 `RichText`。

反向由 `test_markdown_fields_all_appear_in_frontend_source` 守：
清单里的字段若前端源码从未提过，就是一张空头支票，同样失败。

最后一环在浏览器里：UI 冒烟脚本会遍历真实 DOM 的所有文本节点，
发现 `**` 就报错。三层合起来把「后端写 markdown、前端不认识 markdown」堵死。

## 八、一致性测试：同一个数只能有一个来源

反转条件表里的「当前值」与证据卡上的数字**必须是同一个字符串**。
早先两处各自算、各自格式化，临界值上差了最后一位（证据卡 1.85 倍、
反转条件表 1.84 倍），读者无从判断哪个对。

现在表直接引用证据卡的 `display_value`，一致性成为构造保证：

- `test_falsification_values_trace_back_to_evidence` —— 每个当前值都能在证据卡里找到
- `test_falsification_period_matches_source_evidence` —— 报告期也跟着走，不会串期
- `test_revenue_and_profit_evidence_share_the_same_period` —— 同一段推理里的证据同报告期
- `test_cash_row_matches_evidence_card` —— 专门守那条出过错的现金含量行
- `test_attribution_falsification_rows_bind_to_the_right_sub_question`
  —— 子问题 ID 只在同一套模板内唯一，跨模板同名不同义，这条守归因型不串号
- `test_cyclicality_conflict_is_not_produced_for_attribution` / `test_transmission_has_no_conflict_to_report`
  —— 冲突检测必须按命题类型分派，不能按 ID 硬编码
- `test_falsification_conditions_are_monitorable` —— 「阈值依据」一栏必须给出可辨识的出处

## 九、UI 冒烟（真实浏览器）

`frontend/scripts/ui-smoke.mjs` 在无头 Chromium 里跑，补的是 Python 测试看不到的那一段。

| 检查 | 说明 |
| --- | --- |
| 四例结论徽章 | 比对**完整文案**（「现有证据不支持」而非「包含『支持』」——后者对「不支持」也为真，等于没测） |
| 关键区块存在 | `#decompose`、`#evidence` 必须渲染出来 |
| 零 console / pageerror | 全程不得有控制台错误 |
| `**` DOM 扫描 | 遍历所有文本节点，发现未渲染的星号即失败 |
| 三个 tab 可用 | 横向比较出 ≥2 行；追问返回非空且无星号；存为研究任务后出现反转条件条目 |

检出能力已实测：修好之前，它在传输型案例上准确报出了两处 `**` 泄漏。

脚本认 `UI_BASE` 环境变量，因此同一套检查既能打在本地，也能打在线上：

```bash
# 本地
node scripts/ui-smoke.mjs
# 线上（子路径部署）
UI_BASE=http://39.96.194.197/thesis node scripts/ui-smoke.mjs
```

**线上这一遍已经跑过并通过**——四例结论、零控制台错误、
三个 tab 端到端全部符合预期。

## 十、构建期的一道闸门

`npm run build` 会先跑 `scripts/clean-dist.mjs`。
起因是一次真实事故：uvicorn 正挂着 `frontend/dist` 时构建，
带 hash 的旧 bundle 删不掉，而 vite 的 `emptyOutDir` **不会因此失败**，
它只是留着旧文件继续生成新的——`dist/assets` 里堆了 10 个 bundle，
`git add -A` 全带进了提交，而 `index.html` 只引用其中一个。

现在构建前手动清空目录，清不干净就带着「哪个文件删不掉」的信息中止。
（顺带记一条实测结论：本仓库路径含中文，Node 的
`fs.rmSync(dir, { recursive: true })` 在这条路径上**不报错也不删文件**，
所以这层递归由脚本自己走 `unlinkSync` / `rmdirSync`。）

## 十一、澄清环节：回答必须改变下游

这一层（`test_clarifications.py`，20 条）是补一个**产品自己许下但没兑现的承诺**时长出来的。

改动之前，澄清问题连同默认假设一起展示，用户没法回答，而文案里写着
「并可在界面上修改后重跑」——界面上根本没有那个控件。这是本仓库最该消灭的一类错：
**说了一套，做的是另一套，而且不报错。**

现在可以回答了，于是有了两个新的失效模式，两条各有一组断言守着：

**① 回答只改文案、不改判定。** 这种错最难发现——屏幕上明明显示了用户的选择，
结论却还是按默认假设算的。所以「回答必须落到子问题上」不是靠自觉：

| 断言 | 守什么 |
| --- | --- |
| `test_peer_reference_frame_forces_sq01_unverifiable` | 选了「与同业比」后，**估值那条必须改判为无法验证**，且不得再留下一个数值 |
| `test_narrowing_to_revenue_and_profit_drops_the_cash_sub_question` | 命题收窄后，现金流那条**必须移出**并在跳过层里留下原因 |
| `test_uncertain_restructuring_claim_lands_in_applicable_scope` | 答「不确定」时，那条假设必须变成结论里的一条边界声明 |
| `test_answering_is_recorded_in_the_failure_transparency_list` | 改了什么必须出现在用户看得到的清单里 |
| `test_unknown_answer_is_declared_as_having_no_effect` | 自定义回答必须**如实说明它没改动任何子问题**，不许套一个近似口径 |

**② 结论的措辞替一条没跑过的证据说话。** 背离型的结论文案早先写死了
「收入、利润与盈利质量三项均未见恶化」。现金含量那条一旦被移出，这句话就变成了
对一条没跑过的证据的断言——比没有结论更糟。现在文案按**实际在场的子问题**生成，
`test_conclusion_prose_does_not_speak_for_a_dropped_sub_question` 守着。

另外两条是护栏，不是功能：

- `test_no_answers_is_byte_identical_to_before` —— **未回答时输出逐字不变**。
  四条例题的结论写在测试、README 和演示视频里，一个「顺手改进」改掉默认假设，
  等于悄悄换掉了例题的结论。比对时只排除 `run_id` 与 `created_at` 两个每次运行都不同的字段。
- `test_every_option_of_every_question_is_registered` —— 24 个选项一个都不能漏登记。
  漏一个不会报错，只会让那个选项选下去什么都不发生；用户选了、产品没反应，
  与「产品根本没这个功能」在体验上是一样的。反向由
  `test_registered_keys_point_at_real_questions_and_options` 守，防止表里出现
  指不到任何问题或选项的死键。

浏览器里还有一层（`npm run ui:clarify`）：**真实点击**选项 → 重跑 → 断言结论随之改变、
v2 引用了原话、重跑按钮的启用/禁用状态跟着草稿走、全程零控制台错误、无 `**` 泄漏。
Python 测试守的是返回值，这一层守的是「用户能不能真的点到那个控件」。

## 十二、已知未覆盖

诚实列出，不假装完整：

1. **真实故障注入**：超时、限流、鉴权失效没有对着真实接口演练过。
2. **LLM 分支**：`ANTHROPIC_API_KEY` 存在时的解析路径没有自动化测试——
   它的输出不可复现，只能人工核。测试环境一律走规则引擎兜底。
3. **并发**：`/api/verify` 没有做过并发压测。
4. **持久化**：运行记录与已保存任务在内存里，重启即丢，因此没有「重启后数据一致」这类测试。
5. **跨浏览器**：UI 冒烟只在 Chromium 上跑，未覆盖 Firefox / Safari。
6. **移动端**：界面按桌面宽度设计，未做响应式测试。
7. **澄清回答的并发与组合**：测试覆盖了逐条回答，以及「同时答多条」在下游的效果，
   但没做过大量组合的穷举（三类命题 24 个选项，全组合是 3×3×4=36 种，
   加上留空与自定义回答后更大），也没有并发提交同一命题的回答。
